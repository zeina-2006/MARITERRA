01 / OVERVIEW

What Is Computer Vision?

Teaching machines to interpret visual information from the physical world.

Computer Vision is a field of artificial intelligence that enables computers to extract meaningful information from images and video. It combines image processing, mathematical methods, machine learning, and deep learning to interpret visual scenes.

In maritime environments, cameras can capture ships, navigation markers, containers, workers, waves, and port infrastructure. Computer Vision algorithms analyze this visual information and produce outputs such as object locations, classifications, measurements, and movement estimates.

📷

Visual Input

Receives images or video from cameras, drones, satellites, and other imaging systems.

🧠

Visual Understanding

Identifies patterns, objects, shapes, features, and relationships within a scene.

🎯

Recognition

Classifies objects and estimates where they appear in an image.

⚓

Maritime Intelligence

Supports vessel monitoring, port operations, inspection, and situational awareness.

Central idea: A camera captures pixels. A Computer Vision system processes those pixels to produce structured information that software or a human operator can use.

02 / CORE CONCEPTS

How Does a Computer Understand an Image?

Understanding the transformation from raw pixels into useful visual information.

2.1 Pixels and Image Representation

A digital image is represented as a grid of pixels. Each pixel contains numerical information describing its visual value. In a grayscale image, a pixel commonly represents an intensity value. In an RGB image, it contains red, green, and blue channel values.

RGB Pixel = (Red, Green, Blue)

A color image can be represented as a three-dimensional array: height × width × channels. For example, a 1920 × 1080 RGB image contains three color channels for every pixel.

2.2 Image Resolution

Resolution describes the number of pixels used to represent an image. Higher resolution can preserve more visual detail, but it also increases storage, transmission, and processing requirements.

2.3 Features and Patterns

A Computer Vision system may learn or calculate features such as edges, corners, textures, shapes, and spatial arrangements. These features help distinguish a vessel from the surrounding sea or identify structural details in a ship inspection image.

Installed on vessels, terminals, bridges, and port facilities to monitor operational areas.

🚁

Provides aerial views for inspection, coastal monitoring, and infrastructure assessment.

🛰️

Satellite Imagery

Supports large-area maritime observation and vessel-related image analysis.

🌙

Thermal Cameras

Capture infrared information that can help identify heat patterns in low-light conditions.

📡

Radar Images

Represent reflected electromagnetic signals and can complement optical observations.

🔬

Inspection Images

Close-up photographs of machinery, hull surfaces, corrosion, and structural components.

3.1 Optical and Non-Optical Sensors

Ordinary cameras capture visible light. Thermal cameras capture infrared radiation, while radar systems measure reflected radio signals. These sensors produce different kinds of data and require different processing methods.

A radar image should not be treated as if it were an ordinary photograph. Its patterns reflect the sensing process, target properties, and environmental conditions.

More sensors do not automatically mean better recognition. Each source introduces its own calibration, resolution, timing, coverage, and reliability limitations.

04 / IMAGE PROCESSING

Image Processing Fundamentals

Preparing visual information so that useful patterns can be analyzed.

4.1 Resizing and Normalization

Images are often resized to a standard input dimension. Pixel values may also be normalized to a numerical range suitable for a machine-learning model.

4.2 Noise Reduction

Noise can be caused by poor lighting, sensor limitations, transmission errors, or environmental interference. Filters such as Gaussian and median filters can reduce certain types of noise, although excessive filtering may remove useful details.

4.3 Contrast Enhancement

Contrast enhancement makes differences between image regions more visible. Histogram equalization is one technique that redistributes intensity values to improve contrast in some images.

4.4 Edge Detection

Edge detection identifies areas where image intensity changes significantly. These boundaries may correspond to object outlines, ship structures, or other visual features.

4.5 Color Space Conversion

Images can be represented in color spaces such as RGB, HSV, or grayscale. Different representations can make particular image-processing tasks easier.

05 / VISION TASKS

Major Computer Vision Tasks

Different tasks answer different questions about an image or video.

🏷️

Image Classification

Assigns a label to an entire image, such as classifying an image as a cargo vessel or passenger vessel.

📦

Object Detection

Identifies objects and estimates their locations using bounding boxes and class labels.

🧩

Image Segmentation

Assigns labels to individual pixels or regions to identify object shapes and boundaries.

🔍

Feature Extraction

Produces numerical representations of visual patterns for comparison or further analysis.

🎥

Video Analysis

Analyzes sequences of frames to identify events, changes, and movement.

🆔

Visual Re-Identification

Attempts to recognize whether an object observed in different images is the same object.

Classification answers what is in the image? Detection answers what objects are present and where? Segmentation answers which pixels belong to each region or object?

06 / DEEP LEARNING

Deep Learning for Visual Recognition

Learning visual features directly from image data using multi-layer neural networks.

6.1 Convolutional Neural Networks (CNNs)

Convolutional Neural Networks are widely used in image analysis. They apply learnable filters across image regions to detect visual patterns. Early layers may learn simple edges and textures, while deeper layers can represent more complex structures.

Image → Convolution → Activation → Pooling → Feature Maps

6.2 Convolution

A convolution operation applies a small filter, also called a kernel, across an input image or feature map. The operation produces responses that highlight patterns learned during training.

6.3 Activation Functions

Activation functions introduce nonlinearity into neural networks. ReLU is a common activation function that returns zero for negative inputs and the input value for positive inputs.

6.4 Pooling

Pooling reduces the spatial dimensions of feature maps. Max pooling, for example, selects the largest value in a local region.

6.5 Transfer Learning

Transfer learning uses a model previously trained on a large dataset as a starting point for a related task. The model may be used as a feature extractor or fine-tuned using a maritime-specific dataset.

6.6 Vision Transformers

Vision Transformers divide an image into patches and use attention mechanisms to learn relationships between image regions. They provide an alternative to traditional convolution-based architectures.

A model trained on everyday photographs may not perform reliably on maritime images. Differences in camera angle, weather, water reflections, vessel types, and image quality can require domain-specific training and validation.

07 / OBJECT DETECTION

Detecting Objects in Maritime Images

Locating and classifying multiple objects within a single visual scene.

7.1 Bounding Boxes

Object detection systems commonly represent detected objects using rectangular bounding boxes. Each detection may include coordinates, a predicted class, and a confidence score.

Detection = (Class, Bounding Box, Confidence)

7.2 Confidence Score

A confidence score represents the model's estimated confidence in a particular detection under its scoring method. It should not automatically be interpreted as a perfectly calibrated probability that the detection is correct.

7.3 Non-Maximum Suppression (NMS)

Object detectors may generate several overlapping boxes for the same object. Non-Maximum Suppression is a technique that removes selected overlapping detections based on their scores and overlap thresholds.

7.4 Intersection over Union (IoU)

IoU measures the overlap between a predicted bounding box and a ground-truth bounding box.

IoU = Area of Intersection / Area of Union

7.5 Common Detection Architectures

YOLO Family

One-stage detection architectures designed for efficient object detection.

Faster R-CNN

A two-stage detection approach using region proposals followed by object classification and localization.

SSD

Single Shot MultiBox Detector predicts object classes and box locations in a single detection framework.

DETR

Detection Transformer formulates object detection using transformer-based set prediction.

08 / IMAGE SEGMENTATION

Understanding Objects at Pixel Level

Segmentation provides more detailed visual information than a rectangular detection box.

8.1 Semantic Segmentation

Semantic segmentation assigns a class label to every pixel. For example, a maritime image may contain regions labeled as water, vessel, sky, dock, and infrastructure.

8.2 Instance Segmentation

Instance segmentation separates individual objects, even when they belong to the same class. It can distinguish one vessel from another vessel in the same image.

8.3 Panoptic Segmentation

Panoptic segmentation combines semantic and instance segmentation concepts to provide a unified representation of scene regions and individual countable objects.

METHODOUTPUTEXAMPLE
SemanticPixel class labelsAll water pixels receive a water label.

8.4 Maritime Uses

  • Identifying water and land boundaries in coastal imagery.
  • Mapping vessel outlines and port infrastructure.
  • Inspecting damaged or corroded surfaces.
  • Separating objects from complex backgrounds.
09 / OBJECT TRACKING

Tracking Objects Across Video Frames

Following detected objects over time instead of analyzing each frame independently.

9.1 Detection Versus Tracking

Object detection identifies objects in an individual frame. Object tracking attempts to maintain the identity of those objects across successive frames.

9.2 Tracking-by-Detection

A common tracking pipeline first detects objects in each frame, then associates detections between frames using position, motion estimates, appearance features, or combinations of these.

9.3 Tracking Challenges

  • Objects may disappear behind other objects.
  • Several vessels may move close together.
  • Camera movement may change object positions.
  • Lighting and weather may alter visual appearance.
  • Objects may leave and later re-enter the camera view.

9.4 Multi-Object Tracking

Multi-object tracking maintains tracks for multiple objects at the same time. Each track may have an identifier, estimated position, movement history, and confidence information.

Visual tracking is not the same as AIS vessel tracking. AIS provides transmitted vessel information, while visual tracking estimates movement from image sequences. Combining the two requires careful synchronization, identity association, and handling of missing or inaccurate data.

10.1 A Vessel Detection Scenario

Imagine a camera installed at a port entrance. The camera captures a continuous video stream. A detection model analyzes each frame and identifies visible vessels using bounding boxes.

A tracking module can then associate detections across frames. The resulting visual tracks may help estimate movement within the camera's field of view.

10.2 Suez Canal Monitoring Context

In a waterway such as the Suez Canal, visual analytics may support observation of vessels, traffic patterns, and selected infrastructure. However, a camera-based model alone does not provide the complete navigational picture.

Reliable maritime monitoring may require combining visual data with AIS, radar, electronic charts, vessel reports, and information from authorized traffic-management systems.

Computer Vision output should not independently authorize navigation maneuvers or replace approved bridge procedures. Detection errors, occlusion, camera limitations, and delayed processing can create serious operational risks.

11 / VISION SYSTEMS

Designing a Maritime Computer Vision System

A complete system connects cameras, processing hardware, algorithms, and operational interfaces.

11.1 Main System Components

Imaging Hardware

Cameras, lenses, illumination, thermal sensors, or other imaging devices.

Processing Unit

CPU, GPU, or edge-computing hardware used to process image data.

Vision Model

Software that performs classification, detection, segmentation, or tracking.

Data Pipeline

Transfers, preprocesses, stores, and organizes visual information.

Operator Interface

Displays detections, alerts, confidence scores, and relevant visual evidence.

Security Controls

Protects cameras, video streams, stored images, and model infrastructure.

11.2 Edge Processing and Cloud Processing

Edge processing runs analysis close to the camera or onboard system. It can reduce the need to transmit every raw frame and may support lower-latency processing.

Cloud processing can provide scalable computing resources and centralized model management, but it depends on connectivity, bandwidth, security, and data-governance requirements.

11.3 Camera Calibration

Camera calibration estimates parameters that describe the camera's imaging geometry. It is important when visual measurements, geometric interpretation, or multiple-camera alignment are required.

11.4 Sensor Fusion

A maritime system may combine camera detections with radar or AIS observations. This can provide complementary information, but fusion requires synchronized timestamps, coordinate transformations, association logic, and confidence handling.

12.1 Dataset Annotation

Supervised Computer Vision models often require labeled training data. For object detection, annotators draw bounding boxes around objects and assign class labels. Segmentation datasets may require pixel-level masks.

12.2 Dataset Splitting

Data should be divided into training, validation, and test sets. For video-derived datasets, splitting individual adjacent frames randomly can cause leakage because nearly identical frames may appear in both training and testing.

12.3 Evaluation Metrics

  • Precision: How many predicted positive detections were correct?
  • Recall: How many relevant objects were successfully detected?
  • F1-score: Harmonic mean of precision and recall.
  • IoU: Measures overlap between predicted and reference regions.
  • mAP: Mean Average Precision across specified classes and evaluation settings.
  • Latency: Time required to process an image or frame.
F1 = 2 × (Precision × Recall) / (Precision + Recall)

12.4 Testing in Real Conditions

A model should be tested under different lighting, weather, camera positions, distances, vessel types, and background conditions. Laboratory accuracy alone does not prove reliable field performance.

14 / CHALLENGES

Challenges and Limitations

Visual intelligence systems must be evaluated beyond impressive demonstrations.

Lighting Conditions

Night, glare, shadows, and changing sunlight can reduce image quality and recognition accuracy.

Weather and Sea Spray

Fog, rain, spray, and water reflections may obscure objects or create misleading visual patterns.

Occlusion

Objects may be partially hidden by vessels, structures, waves, or other objects.

Dataset Bias

Training data may not represent all vessel types, geographical regions, or operating conditions.

False Detections

Reflections, wakes, birds, and background structures may be incorrectly classified as targets.

Computational Limits

High-resolution video and real-time processing can require substantial computing resources.

Privacy and Security

Video systems may collect sensitive information and require access control, retention policies, and protection.

Adversarial Risks

Manipulated inputs, compromised cameras, or attacks on model pipelines may undermine system reliability.

Critical engineering lesson: A model with high average accuracy may still miss a rare but important object. Evaluation must consider the cost of false negatives, false positives, processing delays, and failure under difficult conditions.

15.1 Responsible Maritime Vision

The future of Computer Vision is not simply about detecting more objects. It is about building systems that are robust, explainable enough for their purpose, secure, privacy-aware, and tested under realistic operating conditions.

In safety-critical maritime environments, visual AI should be integrated with established navigation systems, operating procedures, and qualified human oversight.
